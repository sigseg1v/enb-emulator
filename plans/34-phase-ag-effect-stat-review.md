# Phase AG -- minted effect-base stat review (OWNER APPROVAL REQUIRED)

**Status: blocked on owner review.** This phase does not auto-complete. Each
item below needs a human decision; an agent must NOT guess a stat and wire it
without the owner confirming, because a wrong stat silently buffs/nerfs the
wrong thing (worse than an inert NO_STAT placeholder).

## Background

`db/postgres/seed_item_effects.sql` backfills item->effect links from the
external item dataset. For effect keys that had no row in `item_effect_base`
the generator mints one. 6 of those were wired to a real stat by cloning an
unambiguous existing analog (same stat semantics AND same Equip/Activated
direction) -- see `MINTED_STAT_WIRING` in
`tools/dataimport-jsonl/gen_item_effects_seed.py`. The wired 6:

| EffectID | Name | Var1Stat | Var2Stat | cloned from |
|---|---|---|---|---|
| 252 | Increase Reactor Capacity Self | STAT_ENERGY | - | Increases Reactor capacity Item C |
| 253 | Increase Scan Range | STAT_SCAN_RANGE | - | Scan Range Boost Item C |
| 259 | Projectile Energy Conservation | STAT_PROJECTILE_ENERGY | - | Reduces Projectile Energy Item P |
| 262 | See Cloaked | STAT_SEE_CLOAKED | - | See Cloaked Item C |
| 264 | Worsen Beam Handling Self | STAT_BEAM_ACCURACY | STAT_BEAM_DAMAGE | Worsen Beam Handling Item C |
| 265 | Worsen Missile Handling Self | STAT_MISSILE_ACCURACY | STAT_MISSILE_DAMAGE | Worsen Missile Handling Item C |

(EffectIDs are as generated on a fresh volume; they renumber if the generator
changes. Match by Name, not by id.)

The remaining minted bases were left as inert `NO_STAT` placeholders because
the stat was ambiguous, only an opposite-direction analog existed, or there was
no candidate stat at all. They are listed in
`db/postgres/seed_item_effects.SUS.tsv` (regenerated by the generator's
`--sus-out`). The effects still LINK to the correct items (verified against the
dataset, type-aware); they just do not yet DO anything mechanically.

## What the owner needs to do per row

For each row in `seed_item_effects.SUS.tsv`:
1. Decide the correct `Var1Stat` (and `Var2Stat` for compound effects), the
   `Var1Type` (modifier direction: 1/2 increase, 3/4 reduce, 5 special -- copy
   from a sibling base), and `Buff_Name` (reuse an EXISTING buff string only;
   inventing one resolves to nothing). The suggested_stat column is a starting
   point, NOT a confirmed answer.
2. Add the confirmation to `MINTED_STAT_WIRING` in the generator.
3. Regenerate the seed + recreate the volume (or hand-write an `UPDATE` against
   `item_effect_base` if you do not want to recreate).
4. Tick the row here.

If a row is genuinely a scripted/cosmetic effect (Access Key, Creates
Fireworks, the Loony's Shield Hammer set, Genesis Effect, Create Ten-Gu Fangs)
and not a stat modifier at all, mark it `[x] leave NO_STAT (not a stat effect)`.
